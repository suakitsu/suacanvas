# 安全配置与部署说明

## 私有配置

运行 `python scripts/init-local-env.py` 创建 `.env`。不要覆盖已有部署的配置；脚本也会拒绝覆盖。不要把 `.env`、签名文件、数据目录、用户上传、数据库备份、访问令牌或截图中的凭据提交到 Git。

JWT 不再提供共享默认值，短密钥和旧的 `change-me` 占位值会阻止服务初始化。示例中的数据库和 MinIO 密码为空，Compose 会要求先填写。邮件的发送身份、模板编号及部署主机须由部署者配置。

`V44` 会禁用仍使用原始共享密码哈希的演示管理员，避免新安装带着同一套管理员凭据上线；已更换密码的账户不受该迁移影响。部署者须独立配置自己的管理员，不能依赖历史演示账户。在线管理员注册接口当前关闭；设置 `ADMIN_INVITE_CODE` 不会自动开放注册。该迁移仍需在目标数据库环境验证。

新建 Compose 环境可在后端完成迁移后运行 `python scripts/bootstrap-admin.py`。工具仅允许初始化首个有效管理员，要求交互式输入独立密码，拒绝覆盖已有账号；使用网络隔离的官方 httpd 工具容器计算 bcrypt 哈希，数据库只接收哈希。它不会打开在线注册接口，也不会为账号自动充值。该工具本轮仅做静态审查，没有执行。

普通用户邮箱注册依赖 Tencent SES 验证码服务。未配置邮件凭据、发送身份与模板时，不能把基础容器启动等同于注册流程已经可用；也可以按需配置 GitHub OAuth 登录。

`VIDEO_CONFIG_ENCRYPTION_KEY` 用于加密数据库中的供应商配置，不能任意更换。旧部署若使用了 JWT 回退值，升级前应把原有实际加密值显式配置到该变量，再按迁移方案轮换；否则已有密文将无法解密。新部署会生成与 JWT 独立的值。

历史迁移 `V16`、`V22`、`V23` 中的默认回调地址已改为示例地址。**使用旧版迁移的已有数据库会发生 Flyway 校验和不匹配，不能直接覆盖部署。** 新库可以使用这些脱敏迁移；旧库升级需要在备份和核对迁移内容后单独制定校验和迁移方案，不要盲目执行 `repair`。

## 发布与历史

GitHub `release` 工作流仅允许手动触发；主分支推送不再自动部署。配置 staging/production 环境、SSH 主机和密钥后才能使用。Jenkins 的 `ENABLE_DEPLOY` 默认关闭。发布脚本使用 `git archive`，避免把本地未跟踪秘密和数据打进发布包。

删除当前文件或新增 `.gitignore` 不能清除旧提交。若历史出现真实凭据，先撤销/轮换，再在隔离副本清理所有受影响分支和标签，复扫后协调更新远端及其他克隆。PR 引用、缓存和既有副本也可能保留旧内容；必要时联系 GitHub Support。不要把包含旧秘密的审计副本、报告原文或 Git bundle 上传公开。

历史重置不会自动撤销凭据，也不会清除 GitHub 的只读 PR 引用、平台缓存和其他人的克隆。涉及历史秘密时，应保留私有处理记录并完成凭据轮换，不能把当前工作树扫描无命中当作所有副本均已清除的证明。

## 许可与素材

公开或部署第三方画布前，还应完成对应源码交付，并验证源码下载入口可访问。素材范围记录在 [ASSET_NOTICE.md](../ASSET_NOTICE.md)，第三方许可见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。完整镜像构建、冷启动和数据库迁移需在目标环境验收。

参考：[GitHub 敏感数据清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
